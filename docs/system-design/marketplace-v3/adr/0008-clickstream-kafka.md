# ADR 0008. Кликстрим: Kafka, ключ — IP, хранение 7 суток

**Статус:** принято.

## Контекст

Нужны просмотры карточек лотов: id лота, время, IP, пользователь (пока пустой). Просмотров много, хранить каждый в PostgreSQL дорого, а читать их будут две независимые системы: архив в S3 и детектор абьюза. Потерю части просмотров допускаем: это аналитика, не деньги. Карточка должна открываться, даже если хранилище событий недоступно.

## Варианты

1. **Таблица в PostgreSQL.** Дёшево по коду, но каждый просмотр — запись в основную базу, где идут деньги; растёт без границ.
2. **Очередь BullMQ.** Сообщение забирает один потребитель и удаляется; второй независимой группе его уже не прочитать.
3. **Kafka.** Лог: сообщения хранятся по сроку, каждая группа читает со своим оффсетом, новый потребитель получает историю.
4. **Писать сразу в S3.** Маленькие файлы на каждый просмотр или буфер в API; нет независимых читателей.

## Выбор

Вариант 3. Топик `lot-views`, **три партиции, ключ сообщения — IP посетителя**. Продюсер в API не ждёт: `record()` кладёт событие в ограниченный буфер (`CLICKSTREAM_BUFFER_MAX`), таймер раз в `CLICKSTREAM_LINGER_MS` отправляет пачку с `acks=1`. Kafka недоступна — пачка отбрасывается и считается. Хранение — **по времени, 7 суток** (`retention.ms`), без лимита по объёму.

Ключ — IP, а не id лота, потому что детектор считает просмотры по IP в памяти: если все просмотры одного адреса лежат в одной партиции, их читает одна копия детектора и счётчик верный. Ключ `lotId` разложил бы один IP по партициям, и ни одна копия не увидела бы 300 просмотров.

## Последствия

- Карточка открывается при любом состоянии Kafka (тест и стенд); платим потерей просмотров при её недоступности, падении API (до `CLICKSTREAM_LINGER_MS` просмотров в памяти) или переполнении буфера.
- Диск: измерено ≈ 185 байт на событие; при 100 просмотрах/с и 3 репликах — около 34 ГБ за 7 суток (расчёт в docs/background).
- Массовые запросы с одного IP идут в одну партицию («горячий» ключ), это и есть цель детектора. Параллелизм потребителя ограничен числом партиций (3): увеличивать их позже можно, но ключи перераспределятся.
- Семь суток — запас на остановку архиватора на выходные; долговременная копия — S3 (ADR 0009).
- Один брокер без реплик в Compose; для прода — три брокера (зона 4 карты роста).
