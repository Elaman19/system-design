# ADR 0004. Файлы: сразу в S3, в базе метаданные и ключ

**Статус:** принято.

## Контекст

У лотов есть фото, у сделок будут документы. Файлы большие, нужны всем инстансам app и должны переживать пересоздание контейнера. Диск контейнера для этого не подходит.

## Варианты

1. **Файлы на диске app.** Просто, но файл виден одному инстансу и пропадает вместе с контейнером.
2. **Файлы в PostgreSQL** (`bytea` или large objects). Транзакционно, но раздувает базу, копии и память.
3. **Объектное хранилище S3**, в базе `lot_photos` с ключом объекта, типом и размером.

## Выбор

Вариант 3, с первой версии, а не как зона роста. Загрузка идёт напрямую: app выдаёт подписанную ссылку, SPA пишет файл в закрытый бакет и читает его по подписанной ссылке с коротким сроком. Порядок: сначала файл, затем строка в базе.

## Последствия

- app не гоняет файлы через себя и остаётся без состояния.
- Осиротевшие файлы (загрузка без строки в базе) нужно убирать фоновой задачей.
- Метаданные ограничены схемой: `UNIQUE (s3_key)`, `UNIQUE (lot_id, position)`, допустимые типы и размер.
- Локально в Compose работает SeaweedFS с S3-совместимым API; в приложении схема готова, клиент S3 подключается при реализации загрузки.
