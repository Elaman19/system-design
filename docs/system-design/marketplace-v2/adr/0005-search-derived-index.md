# ADR 0005. Поиск: PostgreSQL на старте, OpenSearch как производный индекс

**Статус:** принято.

## Контекст

Покупателю нужен поиск по каталогу: по названию лота, по названию компании-продавца и по её email, с русской морфологией и опечатками. На старте каталог небольшой.

## Варианты

1. **Всегда только PostgreSQL** (`ILIKE`, полнотекстовый поиск). Дёшево и всегда согласовано, но слабее по опечаткам и ранжированию на большом каталоге.
2. **OpenSearch сразу.** Лучшее качество, но лишний компонент, которого на старте нет нужды содержать.
3. **PostgreSQL на старте, OpenSearch в зоне 1 по сигналу** (поиск не держит p95 ~300 мс или нужны опечатки и ранжирование).

## Выбор

Вариант 3. Когда зона наступает, OpenSearch хранит документ лота с названием, названием и email продавца; индекс - производная копия, источник правды остаётся в PostgreSQL. Индексирует воркер из очереди при изменении лота или компании.

## Последствия

- Допустима задержка между изменением и поиском (eventual consistency); цену и остаток при покупке берут из PostgreSQL, а не из индекса.
- Переименование компании или смена email требует переиндексации её лотов.
- Индекс можно удалить и пересобрать из базы: потери данных нет, меняются только задержка и качество поиска.
